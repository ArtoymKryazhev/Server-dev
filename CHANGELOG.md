# Changelog

## Лабораторная работа 2

### Вопрос 1. Параметры ConfigDict

- `extra='ignore'` — лишние поля во входных данных отбрасываются и не попадают в модель.
- `alias_generator=to_camel` — внешние имена полей строятся в camelCase.
- `populate_by_name=True` — значение можно передать и по имени поля Python, и по алиасу.
- `from_attributes=True` — модель можно собрать из объекта с атрибутами, в том числе из ORM-объекта.

### Вопрос 2. Параметры Field

- `description` — текст поля в JSON Schema и в документации Swagger.
- `default` — значение, если поле не передали.
- `ge` — числовая проверка «больше или равно».
- `kw_only` — поле задаётся только именованным аргументом.
- `examples` — примеры значения в OpenAPI.

### Вопрос 3. Класс Path

`Path` описывает параметр из пути URL: ограничения, описание и примеры попадают в документацию и проверяются до вызова функции. Так параметр пути отделяется от query-параметров и тела запроса.

## Лабораторная работа 3

### Вопрос 1. Параметры SettingsConfigDict

- `env_file` — файл, из которого читаются переменные окружения.
- `env_file_encoding` — кодировка этого файла.
- `extra='ignore'` — переменные, для которых нет полей в классе настроек, не вызывают ошибку.

### Вопрос 2. Параметры mapped_column

- первый аргумент — тип колонки SQLAlchemy (`Integer`, `String`, `Text`, `Boolean`, `TIMESTAMP`);
- `primary_key`, `index`, `unique`, `autoincrement` — ключ, индекс, уникальность и автоинкремент;
- `nullable` — допускается ли `NULL`;
- `default` — значение по умолчанию на стороне Python;
- `server_default` — значение по умолчанию на стороне СУБД;
- `comment` — комментарий колонки в базе;
- `sort_order` — порядок колонки при создании таблицы.

### Вопрос 3. Параметр echo

`echo=True` в `create_async_engine` печатает SQL-запросы, которые отправляет SQLAlchemy. Это удобно при разработке и мешает в рабочей среде: журнал разрастается, а в текст запросов могут попасть данные.
